# Déclaration d'accessibilité

**Date de la présente déclaration :** 23 juillet 2026

Cet outil audite l'accessibilité d'autres sites web — il serait contre-productif qu'il ne soit pas lui-même conforme. Cette déclaration porte sur l'application elle-même (le tableau de bord de l'Auditeur d'accessibilité WCAG), pas sur les sites que l'outil permet de scanner.

## Niveau de conformité visé

Les Règles pour l'accessibilité des contenus Web (WCAG) 2.1, niveau AA, sont la norme de référence pour ce projet.

## Portée

Cette déclaration couvre les pages suivantes de l'application, dans ses deux langues officielles :

- Page d'accueil et formulaire de soumission d'un scan (`/fr`, `/en`)
- Tableau de bord (`/fr/dashboard`, `/en/dashboard`)
- Détail d'un scan et ses violations (`/fr/scans/:id`, `/en/scans/:id`)
- Historique d'un site et graphique de tendance (`/fr/sites/:id`, `/en/sites/:id`)

Elle ne couvre pas les rapports PDF/CSV générés par l'outil (dont le contenu, notamment les extraits HTML des violations, provient de sites externes non contrôlés par ce projet), ni les sites externes eux-mêmes scannés par l'outil.

## Méthodologie

Deux niveaux de vérification ont été appliqués :

1. **Test automatisé** : chaque page listée ci-dessus a été analysée avec axe-core (la même bibliothèque que l'outil utilise pour auditer des sites tiers — voir `docs/adr/0002-playwright-axe-core-plutot-que-moteur-maison.md`), ciblant les critères WCAG 2.1 niveaux A et AA, dans les deux langues. **Résultat au moment de la rédaction : aucune violation détectée automatiquement sur les quatre pages testées.**
2. **Choix de conception favorisant l'accessibilité par construction** : utilisation du GC Design System (lien d'évitement intégré, gestion automatique des associations label/erreur sur les champs de formulaire, structure de landmarks correcte — voir `docs/adr/0003-gc-design-system-plutot-que-bibliotheque-generique.md`), structure de titres hiérarchique sur chaque page, et tableaux de données construits avec des éléments HTML natifs (`<table>`, `<th scope="col">`, `<caption>`) plutôt qu'un composant personnalisé.

## Limitations connues

- **Les tests automatisés ne détectent qu'une partie des problèmes d'accessibilité possibles** (environ 30 à 50 % selon les études du secteur). Un audit manuel complet — navigation au clavier de bout en bout, test avec un lecteur d'écran (NVDA, JAWS, VoiceOver), vérification du contraste sur toutes les combinaisons de couleurs — n'a pas encore été effectué de façon exhaustive sur ce projet.
- Le graphique de tendance (Recharts) sur la page d'historique d'un site n'expose pas encore d'alternative textuelle équivalente au contenu visuel (par exemple un tableau de données sous-jacent déjà présent sur la même page atténue partiellement ce manque, puisque les mêmes valeurs y sont listées).
- Ces limitations seront réduites au fil des prochaines itérations du projet plutôt que passées sous silence.

## Rétroaction et contact

Si vous rencontrez un obstacle à l'accessibilité en utilisant cet outil, vous pouvez le signaler via une issue sur le dépôt GitHub ou en contactant l'auteure via son profil [github.com/itsGween](https://github.com/itsGween).

# Accessibility Statement

**Date of this statement:** July 23, 2026

This tool audits the accessibility of other websites — it would be counterproductive for it not to be accessible itself. This statement covers the application itself (the WCAG Accessibility Auditor dashboard), not the sites the tool is used to scan.

## Conformance target

The Web Content Accessibility Guidelines (WCAG) 2.1, level AA, is the reference standard for this project.

## Scope

This statement covers the following application pages, in both official languages:

- Home page and scan submission form (`/fr`, `/en`)
- Dashboard (`/fr/dashboard`, `/en/dashboard`)
- Scan detail and its violations (`/fr/scans/:id`, `/en/scans/:id`)
- Site history and trend chart (`/fr/sites/:id`, `/en/sites/:id`)

It does not cover the PDF/CSV reports generated by the tool (whose content, notably HTML snippets from violations, originates from external sites not controlled by this project), nor the external sites scanned by the tool itself.

## Methodology

Two levels of verification were applied:

1. **Automated testing**: each page listed above was analyzed with axe-core (the same library the tool uses to audit third-party sites — see `docs/adr/0002-playwright-axe-core-plutot-que-moteur-maison.md`), targeting WCAG 2.1 level A and AA criteria, in both languages. **Result at the time of writing: zero violations automatically detected across the four pages tested.**
2. **Design choices favoring accessibility by construction**: use of the GC Design System (built-in skip-to-content link, automatic label/error association on form fields, correct landmark structure — see `docs/adr/0003-gc-design-system-plutot-que-bibliotheque-generique.md`), a logical heading hierarchy on every page, and data tables built with native HTML elements (`<table>`, `<th scope="col">`, `<caption>`) rather than a custom component.

## Known limitations

- **Automated testing only detects a subset of possible accessibility issues** (roughly 30-50% per industry studies). A complete manual audit — end-to-end keyboard navigation, screen reader testing (NVDA, JAWS, VoiceOver), contrast verification across every color combination — has not yet been performed exhaustively on this project.
- The trend chart (Recharts) on a site's history page does not yet expose a text alternative equivalent to the visual content (a data table with the same values already present on the same page partially mitigates this gap).
- These limitations will be reduced over future iterations of the project rather than glossed over.

## Feedback and contact

If you encounter an accessibility barrier while using this tool, you can report it via a GitHub issue on the repository, or by contacting the author through their [github.com/itsGween](https://github.com/itsGween) profile.
